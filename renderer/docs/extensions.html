How extensions work

Meteor extensions are declarative. They describe what to add, and Meteor does the rest. No extension code runs inside the app, so a manifest can't crash Meteor or read your files on its own.

Slash commands

Reusable prompts such as /review or /commit, typed in the chat box.

Instructions

A short style or behaviour note added to every chat, like "keep answers short".

MCP servers

Give Meteor new tools, such as memory or a database, through the open Model Context Protocol.

Anything that needs to run code is an MCP server. You write the server (in any language), and the extension tells Meteor how to start it.

Quick start

Make a folder and add a file called meteor-extension.json:

meteor-extension.json
{
  "id": "hello-extension",
  "name": "Hello extension",
  "version": "0.1.0",
  "description": "A minimal example: one slash command and one instruction.",
  "author": "You",
  "commands": [
    {
      "name": "hello",
      "description": "Greet the user in a friendly way",
      "prompt": "Say hello and then help with this: {{input}}"
    }
  ],
  "instructions": "When the user says hello, answer in one friendly sentence."
}
  1. In Meteor, open Extensions in the sidebar.
  2. Choose Install from file and pick your meteor-extension.json.
  3. Read the confirmation, then press Install.
  4. In any chat, type /hello fix my bug. Meteor expands it into your prompt and sends it.

The same file lives in the Meteor repository under examples/hello-extension/.

Manifest reference

An extension must include at least one of commands, instructions or mcpServers. Meteor checks every file when you install it and tells you what to fix.

FieldTypeDescription
idstring, requiredUnique name. 2–39 characters: lowercase letters, numbers and dashes. Installing the same id again replaces the old version.
namestring, requiredShown in the store. Up to 60 characters.
versionstring, requiredVersion like 1.0.0.
descriptionstring, requiredOne or two sentences. Up to 300 characters.
authorstringYour name or team. Up to 80 characters.
homepagestringAn https:// link to your source or docs.

instructionsstringUp to 4,000 characters, added to every chat.
mcpServersobjectUp to 10 MCP servers, in the same format as Meteor's Plugins settings.

Slash commands

Each command is a name, a description and a prompt template.

"commands": [
  {
    "name": "review",
    "description": "Review code for bugs, security and clarity",
    "prompt": "Review the following code and list problems by severity.\n\n{{input}}"
  }
]
FieldRules
nameLowercase letters, numbers and dashes, starting with a letter. The user types it as /name. These names are reserved: clear, new, help, model, reasoning.
descriptionUp to 120 characters. Shown in /help.
promptUp to 4,000 characters. {{input}} is replaced by whatever the user typed after the command. Without {{input}}, their text is added at the end.

The expanded prompt is what appears in the chat, so users can always see exactly what was sent. Attach files with @ before running a command and Meteor includes them as usual.

Instructions

Instructions are added to Meteor's system prompt under an "Extension instructions" heading. Use them for stable preferences, not for tasks.

  • Keep them short and specific. Several installed extensions share the same prompt.
  • Write what Meteor should do, such as "answer with code first", instead of long lists of rules.
  • Avoid telling Meteor to ignore its other instructions. Conflicting instructions give unpredictable results.

MCP servers

Use mcpServers to add tools. Each key is a server name, and the value is the same config you would use in Meteor's Plugins settings.

"mcpServers": {
  "server": {
    "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-memory"]
  }
}

Remote servers use a URL instead of a command:

"mcpServers": {
  "docs": { "type": "http", "url": "https://example.com/mcp" }
}
  • On install, each server is added to Plugins as ext-<id>-<name>. Removing the extension removes them again.
  • Meteor only offers MCP tools to the model when a message mentions @, "mcp" or a server name, so tell users what to mention in your description.
  • Never put secrets such as API keys in a published manifest. Ask users to add keys in Settings → Plugins after installing.

Test locally

  1. Install your file with Extensions → Install from file. You can reinstall any time to update it.
  2. Type /help in a chat. Your commands should be listed.
  3. Run each command once. Check the expanded prompt in the chat gives the answer you want.
  4. For MCP servers, open Settings → Plugins and press test to confirm the server starts.
  5. Extensions → Open folder shows where installed extensions are stored (~/.config/meteor/extensions/).

Publish to the store

The store reads a single file, registry/extensions.json, from the Meteor repository on GitHub. To list your extension:

  1. Fork YlsooAI/MeteorIDE.
  2. Add your whole manifest as a new object in the extensions array of registry/extensions.json.
  3. Open a pull request. Describe what the extension does and, for MCP servers, where its source lives.
{
  "extensions": [
    { "id": "code-review", "name": "Code review", "version": "1.0.0", "...": "..." },
    { "id": "your-extension", "name": "Your extension", "version": "1.0.0", "...": "..." }
  ]
}

Entries that fail validation are skipped, so check that your manifest installs from a file first. To release an update, raise version and open another pull request.

What reviewers look forClear descriptions, no secrets, MCP servers from sources people can read, and commands that do what their description says.

Safety

  • Meteor shows what an extension will do before installing it, including the exact command of every MCP server.
  • MCP servers run on the user's computer with their permissions. Only install extensions you trust.
  • Meteor validates the manifest strictly. Unknown shapes, oversized text and reserved command names are rejected.
  • The manifest itself can't run code in the Meteor window. Only the MCP servers it lists run code.

Troubleshooting

ProblemFix
"Not valid JSON"Check for trailing commas and that all text uses straight double quotes. Paste the file into a JSON validator.
"id must be 2-39 characters"Use only lowercase letters, numbers and dashes, such as my-tool.
"is reserved by Meteor"Rename the command. /clear, /new, /help, /model and /reasoning are built in.
Command does nothingCommands are matched at the very start of the message. Put the command first and check /help.
MCP tools never runMention @, "mcp" or the server name in your message, then check the server under Settings → Plugins.
Store says "Offline"Meteor falls back to the built-in list. Installing from a file always works offline.
